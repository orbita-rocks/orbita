Orbita is starting: {{ .Values.leader.replicas }} leader group members and {{ .Values.worker.replicas }} workers.

Watch them come up:

  kubectl --namespace {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }} --watch

Clients connect to one address, and any worker answers:

  {{ include "orbita.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}

From your laptop:

  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "orbita.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
  orbita cluster describe
  orbita keyspace create demo
  orbita set demo greeting hello
  orbita get demo greeting

Nodes talk to each other on port {{ .Values.service.peerPort }}, through the headless Services
only. It is not on the client Service, so setting service.type to LoadBalancer
exposes port {{ .Values.service.port }} and nothing else. Keep it that way: peer traffic uses a
private framing that is compatible only within a cluster version window.
{{ if not .Values.networkPolicy.enabled }}
Nothing stops another pod in this cluster from connecting to port {{ .Values.service.peerPort }}. Set
networkPolicy.enabled if your CNI enforces policy.
{{- end }}

Before you upgrade this release, read docs/UPGRADES.md. Readiness here means
the node has rejoined and caught up, while liveness means only that the process
answers. Keep those two checks separate during an incident.
{{- if .Values.leader.firstRaftUpgrade }}

FIRST RAFT UPGRADE: the leader StatefulSet is OnDelete because the old pods
cannot vote for the first new pod during a normal rolling update.

Replace two voters together, then wait for their two-of-three quorum:

  kubectl --namespace {{ .Release.Namespace }} delete pod {{ include "orbita.fullname" . }}-leader-1 {{ include "orbita.fullname" . }}-leader-2
  kubectl --namespace {{ .Release.Namespace }} wait --for=condition=Ready pod/{{ include "orbita.fullname" . }}-leader-1 pod/{{ include "orbita.fullname" . }}-leader-2 --timeout=10m

Replace the last old voter and wait for it to catch up:

  kubectl --namespace {{ .Release.Namespace }} delete pod {{ include "orbita.fullname" . }}-leader-0
  kubectl --namespace {{ .Release.Namespace }} wait --for=condition=Ready pod/{{ include "orbita.fullname" . }}-leader-0 --timeout=10m

Then run Helm again with leader.firstRaftUpgrade=false. This restores ordinary
readiness-gated RollingUpdate for every later release.
{{- end }}
{{ if not .Values.objectStore.endpoint }}
Warning: no object store is configured, so compacted data stays on local disks
and replacing a worker means rehydrating it from its replicas. Set
objectStore.endpoint before this cluster holds anything you care about.
{{- end }}
{{- if and .Values.objectStore.endpoint (eq (include "orbita.credentialSource" .) "static") }}

This release authenticates to object storage with a static access key. On AWS,
prefer objectStore.credentialSource=instance-profile with objectStore.roleArn:
the nodes then read short-lived credentials from the instance metadata service
and assume the role that carries the bucket policy, and this release deploys no
Secret at all. Static keys remain the right answer for MinIO and R2, which
offer nothing else.
{{- end }}
